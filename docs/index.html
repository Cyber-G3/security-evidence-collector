PIPELINE

Collect. Normalize. Verify. Map.

The project deliberately separates technical observations from compliance interpretation.

01

Collect

Read verifiable repository metadata and security configuration from the GitHub REST API.

02

Normalize

Convert results into explicit PASS, FAIL, UNKNOWN, NOT_APPLICABLE, or ERROR states.

03

Verify

Hash generated artifacts and detect missing or modified evidence through the manifest.

04

Map

Relate technical checks to internal controls and supporting ISO 27001 / NIS2 references.

QUICK START

Generate your first collection command.

Enter a public GitHub repository in OWNER/REPOSITORY format. This page never asks for or stores a GitHub token.

The landing page does not run repository scans in the browser. Collection remains local or in GitHub Actions so credentials and evidence stay under your control.

OUTPUT

A structured Evidence Pack, not a screenshot folder.

Each collection creates machine-readable evidence, deterministic findings, control mappings, framework references, a human-readable report, and an integrity manifest.
